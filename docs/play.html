Learn Git and GitHub by doing it.

A real Git engine runs in this page, with a GitHub to push to. Twenty-three lessons take you from your first commit to opening a pull request and surviving the push that gets rejected. The graph answers every command as you type it. Nothing to install, nothing you can break.

The course

Jump to any lesson. Your progress is remembered on this device, so you can leave and come back.

What it understands

add, commit (with --amend), restore, branch, switch, checkout, merge, rebase, reset, revert, cherry-pick, tag, stash, log, reflog, status. References work as they really do: main, HEAD, HEAD~2, HEAD^, a tag, or a short hash. edit <file> stands in for changing a file in your editor, and teammate stands in for a colleague pushing to the shared repository. On the GitHub side: git remote add, git push, git fetch, git pull, gh pr create, gh pr merge.

Why the faded circles matter

A commit nothing points at any more. Reset and rebase both leave them behind. They are not gone, and that is the single most reassuring fact in Git: git reflog still lists them, and a reset back to that hash brings the work home.

Where it stops

File contents are not modelled, so a conflict here is about which side wins rather than editing the text between the markers. Everything else is real: history, branches, remotes, pull requests, and conflicts. For the messages Git prints see the conflict errors, and for the underlying model see the diagrams.
