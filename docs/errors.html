Git errors, decoded.

The message Git printed, what it actually means, and the fix. Paste any part of the error to filter.

... errors decoded so far. Yours is missing? Paste it in Discussions and it will be added.

fatal: not a git repository (or any of the parent directories): .git#

This folder, and none above it, contains a .git directory. You are outside the project.

cd <project-folder>

Nine times out of ten you are in the wrong directory.

git init

Only if this folder truly should become a new repository.

See also: Put an existing project on GitHub

remote: Repository not found.#

The URL has a typo, the repository is private and you lack access, or you are authenticated as the wrong account.

git remote -v

Check the exact owner and name. Case matters on some hosts.

gh auth status

Confirm which account you are signed in as; private repositories 404 instead of revealing they exist.

See also: Change the remote URL

See also: Stop Git asking for my password every time

git@github.com: Permission denied (publickey).#

The host never received a key it recognizes: no key loaded, key not added to your account, or an HTTPS problem disguised by an SSH URL.

Full answer with danger level and undo: Fix: Permission denied (publickey)

fatal: Authentication failed for 'https://github.com/...'#

The credential your machine sent is wrong, expired, or a password where a token is required.

gh auth login

The quickest reset on GitHub: sign in through the browser and git is fixed too.

git config --global credential.helper manager

Then push again; the credential manager prompts fresh. GitHub removed password authentication in August 2021, so a real password can never work.

See also: Stop Git asking for my password every time

See also: HTTPS or SSH for remotes, which and why

The remote has commits you do not have. Git refuses to overwrite them.

Same cause as non-fast-forward: someone pushed before you.

error: Your local changes to the following files would be overwritten by merge#

The operation needs to rewrite files you have edited but not committed. Git refuses to destroy them silently.

git stash -u

Set your edits aside, run the merge or switch again, then git stash pop.

git restore <file>

Or discard the edits if they were disposable. This loses them.

Not an error. You checked out a commit or tag directly, so you stand on a snapshot instead of a branch.

fatal: unable to auto-detect email address#

Git has no identity to stamp into the commit.

Full answer with danger level and undo: Fix: Please tell me who you are

error: cannot pull with rebase: You have unstaged changes#

A rebase must start from a clean tree, and yours has edits.

fatal: unable to access '...': Could not resolve host: github.com#

A network problem, not a Git problem: no internet, VPN or proxy in the way, or DNS down.

ping github.com

If this fails, fix the network first.

git config --global --unset http.proxy

A stale proxy setting from an old network is a classic cause; check with git config --get http.proxy

fatal: unable to access '...': SSL certificate problem#

Something intercepts HTTPS, usually a corporate proxy with its own certificate that Git does not trust yet.

git config --global http.sslCAInfo <path-to-company-ca.pem>

Point Git at your company's CA bundle; IT provides the file. Never solve this with sslVerify false outside a throwaway test.

error: RPC failed; HTTP 408 curl 22 (or 400, or curl 55)#

A large push choked, often against a proxy or server limit on request size.

git config http.postBuffer 157286400

Raises the HTTP buffer to 150 MB for this repository.

git push origin <branch> --no-thin

If it persists, push over SSH instead; SSH has no such limit.

See also: Fix: push rejected because a file exceeds 100 MB

error: pathspec '<name>' did not match any file(s) known to git#

The file or branch name does not exist as typed: a typo, wrong case, or a branch you have not fetched.

git status

See the real file names Git knows.

git fetch && git branch -a

If it was a branch name, confirm it exists on the remote and fetch first.

fatal: a branch named '<name>' already exists#

You are creating a branch whose name is taken.

git switch <name>

If you meant to continue on it.

git branch -D <name> && git switch -c <name>

If the old one is disposable and you want a fresh start here. -D discards its unmerged commits.

fatal: destination path '<folder>' already exists and is not an empty directory#

git clone creates the folder, and a folder with that name is already there.

git clone <url> <other-name>

Clone into a different folder name.

rm -rf <folder> && git clone <url>

Or remove the old folder first, if it is disposable.

error: remote origin already exists#

You are adding a remote named origin to a repository that already has one.

fatal: 'origin' does not appear to be a git repository#

You pushed or pulled against a remote name that is not configured here.

Your branch and 'origin/main' have diverged#

Both you and the remote gained different commits since you last synced.

Full answer with danger level and undo: Fix: Your branch and origin have diverged

Your branch is ahead of 'origin/main' by N commits#

Not an error. You have local commits the remote lacks; push when ready.

git push

That is the whole fix. git log origin/main..HEAD --oneline shows what will go up.

fatal: bad object HEAD (or: loose object is corrupt)#

The object database is damaged, usually a crash, a full disk, or a synced-folder service fighting over .git.

git fsck --full

Survey the damage.

git clone <url> ../<repo>-fresh

With a remote, the honest repair: clone fresh, copy over your uncommitted work. Keeping a repository inside OneDrive or Dropbox is the classic cause; exclude .git from syncing.

See also: Recover a lost commit or branch

error: unable to create file <path>: Filename too long#

Windows' 260-character path limit, hit by deep folder structures.

Full answer with danger level and undo: Fix: Filename too long on Windows

error: invalid path '<name>'#

The repository contains a file name Windows forbids: reserved names like aux or con, or characters like colon and question mark, committed from Linux or macOS.

git clone --no-checkout <url> && cd <repo> && git sparse-checkout set --no-cone '/*' '!<bad-path>'

Clone without touching disk, exclude the offending path, then git checkout. The lasting fix is renaming the file on a non-Windows machine.

See also: Work with a huge repository without downloading it all

warning: You appear to have cloned an empty repository.#

Not an error. The remote exists but has no commits yet.

Full answer with danger level and undo: Put an existing project on GitHub

fatal: this operation must be run in a work tree#

You are inside the .git folder itself, or in a bare repository that has no working files by design.

cd ..

If you wandered into .git, step out.

git clone <bare-repo-path> <folder>

A bare repo (server-side storage) is worked on by cloning it, never directly.

See also: Clone a repository

error: Pulling is not possible because you have unmerged files.#

An earlier merge stopped at conflicts and is still waiting for you to finish it.

hint: You have divergent branches and need to specify how to reconcile them.#

Newer Git asks you to choose a pull strategy once instead of silently merging.

git config --global pull.rebase true

The usual right answer: remote commits land, yours replay on top, history stays straight.

git config --global pull.ff only

The strict alternative: pull succeeds only when nothing diverged, and asks you to decide otherwise.

See also: Fix: Your branch and origin have diverged

See also: Get the latest changes from the remote

fatal: could not read Username for 'https://github.com': No such device or address#

Git wanted to ask for credentials but no terminal was attached, the classic CI and script failure.

git remote set-url origin https://x-access-token:${TOKEN}@github.com/<owner>/<repo>.git

In CI, inject a token; in GitHub Actions, actions/checkout handles this for you.

git config --global credential.helper manager

On your own machine, store credentials once so Git never needs to ask.

See also: Stop Git asking for my password every time

fatal: early EOF (the remote end hung up unexpectedly)#

A large clone or fetch died mid-transfer: unstable connection, proxy timeout, or a server cutting long downloads.

git clone --depth 1 <url>

A shallow clone transfers a fraction of the data and almost always survives.

git fetch --unshallow

Then deepen to full history in resumable steps once inside.

See also: Clone a repository

See also: Work with a huge repository without downloading it all

xcrun: error: invalid active developer path (/Library/Developer/CommandLineTools)#

A macOS update removed the command line tools, and git on a Mac lives inside them.

xcode-select --install

Reinstalls the tools; git returns with them. This repeats after most major macOS upgrades.

Could not open a connection to your authentication agent.#

ssh-add needs the ssh-agent process, and none is running in this shell.

eval "$(ssh-agent -s)" && ssh-add

Starts the agent and loads your key, macOS and Linux.

Get-Service ssh-agent | Set-Service -StartupType Automatic; Start-Service ssh-agent

Windows PowerShell, once as administrator; the agent then starts with the system.

Your pull is set to fast-forward only, and the branches have diverged, so a decision is needed.

git pull --rebase

The usual answer: remote commits land, yours replay on top.

git pull --no-ff

Or take a merge commit this once. The strict setting did its job: it made the divergence visible instead of merging silently.

The wrapper line under most push rejections; the real reason is the line above it, usually non-fast-forward.

fatal: could not create work tree dir '<name>': Permission denied#

You are cloning into a folder your user cannot write to.

cd ~ && git clone <url>

Clone somewhere you own. System folders and other users' paths need rights you should rarely grant to Git.

error: insufficient permission for adding an object to repository database .git/objects#

Files inside .git belong to another user, typically after running Git with sudo once or sharing a repo folder.

sudo chown -R $(whoami) .git

Return the repository to your user, then never run Git with sudo again.

See also: Fix: detected dubious ownership in repository

error: cannot lock ref 'refs/remotes/origin/<branch>': unable to resolve reference#

A stale or corrupted remote-tracking reference, often after an interrupted fetch.

git update-ref -d refs/remotes/origin/<branch>

Delete the broken reference.

git fetch --prune

Rebuilds it cleanly from the remote.

See also: Remove local references to deleted remote branches

error: cannot lock ref 'refs/heads/<x>/<y>': 'refs/heads/<x>' exists#

Branch names are paths: a branch named x blocks any branch named x/y, and the reverse.

git branch -m <x> <x>-old

Rename or delete the conflicting branch; then create the nested name. Agree on a naming scheme (feature/..., fix/...) before the team collides again.

See also: Rename a branch

See also: Delete a branch, locally and on the remote

fatal: bad revision 'HEAD'#

The repository has no commits yet, so HEAD points at nothing.

git add . && git commit -m "Initial commit"

The first commit brings HEAD to life; every log and diff command works after it.

See also: Put an existing project on GitHub

fatal: ambiguous argument 'HEAD': unknown revision or path not in the working tree.#

Same family: an empty repository, or a name Git cannot tell apart from a file.

git log --oneline

Empty repo? Commit first. Otherwise separate revisions from paths with a double dash:

git log -- <file>

Everything after -- is a path, never a revision.

See also: See the commit history

error: The following untracked working tree files would be overwritten by checkout#

The branch you are switching to tracks files that exist here untracked; Git refuses to destroy them silently.

mkdir -p ../backup && mv <file> ../backup/

Move them aside if they matter, then switch.

git clean -nd

Or preview and delete them if disposable: -fd deletes what -nd lists.

See also: Delete untracked files from the working tree

See also: Set work aside temporarily (stash)

error: unable to unlink old '<file>': Permission denied#

Something holds the file open: an editor, a running process, or an antivirus scan, most often on Windows.

<close the app using the file, then retry>

IDEs and dev servers are the usual holders. Persistent cases are the antivirus; exclude the repository folder from real-time scanning.

See also: Fix: Unable to create .git/index.lock: File exists

fatal: '<branch>' is already checked out at '<path>'#

Worktrees guarantee one checkout per branch, and that branch lives in another folder.

git worktree list

See where. Work there, or check out a different branch here.

git worktree remove <path>

Or retire that worktree if it is finished.

Reverting a merge needs to know which parent line survives.

The network blocks port 22, the classic corporate and campus firewall move.

printf "Host github.com\n HostName ssh.github.com\n Port 443\n" >> ~/.ssh/config

GitHub speaks SSH on port 443 too; this tunnels past most firewalls. Or use HTTPS remotes on that network.

You added a folder that is itself a Git repository; it would be recorded as an empty pointer, confusing every clone.

git rm --cached <folder>

fatal: in unpopulated submodule '<path>'#

cd .. && git submodule update --init --recursive

fatal: no submodule mapping found in .gitmodules for path '<path>'#

error: could not apply <hash>... <message>#

A rebase or cherry-pick hit a conflict on this commit and paused for you.

git status

Fix the conflicted files, git add them, then:

git rebase --continue

Or --skip to drop this commit, or --abort to unwind everything. Cherry-pick uses the same three.

CONFLICT (modify/delete): <file> deleted in <ref> and modified in <ref>#

One side deleted the file, the other edited it; Git cannot choose.

git add <file>

Keep the modified version, or:

git rm <file>

Honor the deletion. Either way, continue the merge or rebase after.
