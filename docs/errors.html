Git errors, decoded.

fatal: not a git repository (or any of the parent directories): .git#

This folder, and none above it, contains a .git directory. You are outside the project.

cd <project-folder>

Nine times out of ten you are in the wrong directory.

git init

Only if this folder truly should become a new repository.

See also: Put an existing project on GitHub

remote: Repository not found.#

The URL has a typo, the repository is private and you lack access, or you are authenticated as the wrong account.

git remote -v

Check the exact owner and name. Case matters on some hosts.

gh auth status

Confirm which account you are signed in as; private repositories 404 instead of revealing they exist.

See also: Change the remote URL

See also: Stop Git asking for my password every time

git@github.com: Permission denied (publickey).#

The host never received a key it recognizes: no key loaded, key not added to your account, or an HTTPS problem disguised by an SSH URL.

fatal: Authentication failed for 'https://github.com/...'#

The credential your machine sent is wrong, expired, or a password where a token is required.

gh auth login

The quickest reset on GitHub: sign in through the browser and git is fixed too.

git config --global credential.helper manager

Then push again; the credential manager prompts fresh. GitHub removed password authentication in August 2021, so a real password can never work.

fatal: unable to access '...': Could not resolve host: github.com#

A network problem, not a Git problem: no internet, VPN or proxy in the way, or DNS down.

ping github.com

If this fails, fix the network first.

git config --global --unset http.proxy

A stale proxy setting from an old network is a classic cause; check with git config --get http.proxy

fatal: unable to access '...': SSL certificate problem#

Something intercepts HTTPS, usually a corporate proxy with its own certificate that Git does not trust yet.

git config --global http.sslCAInfo <path-to-company-ca.pem>

Point Git at your company's CA bundle; IT provides the file. Never solve this with sslVerify false outside a throwaway test.

error: RPC failed; HTTP 408 curl 22 (or 400, or curl 55)#

A large push choked, often against a proxy or server limit on request size.

git config http.postBuffer 157286400

Raises the HTTP buffer to 150 MB for this repository.

git push origin <branch> --no-thin

If it persists, push over SSH instead; SSH has no such limit.

Your branch is ahead of 'origin/main' by N commits#

Not an error. You have local commits the remote lacks; push when ready.

git push

fatal: bad object HEAD (or: loose object is corrupt)#

The object database is damaged, usually a crash, a full disk, or a synced-folder service fighting over .git.

git fsck --full

Survey the damage.

git clone <url> ../<repo>-fresh

With a remote, the honest repair: clone fresh, copy over your uncommitted work. Keeping a repository inside OneDrive or Dropbox is the classic cause; exclude .git from syncing.

error: unable to create file <path>: Filename too long#

error: invalid path '<name>'#

The repository contains a file name Windows forbids: reserved names like aux or con, or characters like colon and question mark, committed from Linux or macOS.

git clone --no-checkout <url> && cd <repo> && git sparse-checkout set --no-cone '/*' '!<bad-path>'

Clone without touching disk, exclude the offending path, then git checkout. The lasting fix is renaming the file on a non-Windows machine.

A bare repo (server-side storage) is worked on by cloning it, never directly.

hint: You have divergent branches and need to specify how to reconcile them.#

Newer Git asks you to choose a pull strategy once instead of silently merging.

git config --global pull.rebase true

The usual right answer: remote commits land, yours replay on top, history stays straight.

git config --global pull.ff only

The strict alternative: pull succeeds only when nothing diverged, and asks you to decide otherwise.

fatal: could not read Username for 'https://github.com': No such device or address#

Git wanted to ask for credentials but no terminal was attached, the classic CI and script failure.

git remote set-url origin https://x-access-token:${TOKEN}@github.com/<owner>/<repo>.git

In CI, inject a token; in GitHub Actions, actions/checkout handles this for you.

git config --global credential.helper manager

On your own machine, store credentials once so Git never needs to ask.

xcrun: error: invalid active developer path (/Library/Developer/CommandLineTools)#

A macOS update removed the command line tools, and git on a Mac lives inside them.

xcode-select --install

Reinstalls the tools; git returns with them. This repeats after most major macOS upgrades.

ssh-add needs the ssh-agent process, and none is running in this shell.

eval "$(ssh-agent -s)" && ssh-add

Starts the agent and loads your key, macOS and Linux.

Get-Service ssh-agent | Set-Service -StartupType Automatic; Start-Service ssh-agent

Windows PowerShell, once as administrator; the agent then starts with the system.

Or take a merge commit this once. The strict setting did its job: it made the divergence visible instead of merging silently.

error: insufficient permission for adding an object to repository database .git/objects#

Files inside .git belong to another user, typically after running Git with sudo once or sharing a repo folder.

sudo chown -R $(whoami) .git

error: cannot lock ref 'refs/remotes/origin/<branch>': unable to resolve reference#

A stale or corrupted remote-tracking reference, often after an interrupted fetch.

git update-ref -d refs/remotes/origin/<branch>

git fetch --prune

Rebuilds it cleanly from the remote.

error: cannot lock ref 'refs/heads/<x>/<y>': 'refs/heads/<x>' exists#

Branch names are paths: a branch named x blocks any branch named x/y, and the reverse.

git branch -m <x> <x>-old

Rename or delete the conflicting branch; then create the nested name. Agree on a naming scheme (feature/..., fix/...) before the team collides again.

fatal: bad revision 'HEAD'#

The repository has no commits yet, so HEAD points at nothing.

git add . && git commit -m "Initial commit"

The first commit brings HEAD to life; every log and diff command works after it.

See also: Put an existing project on GitHub

fatal: ambiguous argument 'HEAD': unknown revision or path not in the working tree.#

Same family: an empty repository, or a name Git cannot tell apart from a file.

git log --oneline

Empty repo? Commit first. Otherwise separate revisions from paths with a double dash:

git log -- <file>

Everything after -- is a path, never a revision.

error: The following untracked working tree files would be overwritten by checkout#

The branch you are switching to tracks files that exist here untracked; Git refuses to destroy them silently.

mkdir -p ../backup && mv <file> ../backup/

Move them aside if they matter, then switch.

git clean -nd

Or preview and delete them if disposable: -fd deletes what -nd lists.

IDEs and dev servers are the usual holders. Persistent cases are the antivirus; exclude the repository folder from real-time scanning.

Or retire that worktree if it is finished.
