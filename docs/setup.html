From zero to first push.

Six steps, in order, nothing skipped. Twenty minutes from a bare machine to your work published.

1. Install Git

Windowswinget install Git.Git
macOSbrew install git
Debian, Ubuntusudo apt install git
Fedorasudo dnf install git
Verifygit --version

macOS without Homebrew: run git once and accept the developer tools prompt. Any other system: git-scm.com/downloads. Anything 2.23 or newer is fine.

2. Tell Git who you are

git config --global user.name "<your name>"
git config --global user.email "<your email>"
git config --global init.defaultBranch main

Use the same email as your GitHub account, or your commits will not count on your profile.

3. One key, every host

ssh-keygen -t ed25519 -C "<your email>"
cat ~/.ssh/id_ed25519.pub

Copy the output into GitHub: Settings, SSH and GPG keys, New SSH key. The same public key works on GitLab, Bitbucket, and Azure DevOps. Test with ssh -T git@github.com; it should greet you by name.

4. Your first repository

Joining something that exists:

git clone git@github.com:<user>/<repo>.git

Publishing something of yours:

git init -b main
git add . && git commit -m "Initial commit"
gh repo create <name> --public --source . --push

The last command uses GitHub CLI. Without it: create an empty repository on the website, then git remote add origin <url> and git push -u origin main.

5. The loop you will run forever

git status -sb
git add <file>
git commit -m "<what and why>"
git push

Edit, stage, commit, push. Everything else is a variation. See what each step actually moves, once, and the commands stop being magic words.

6. When it goes wrong

It will, for everyone, forever. That is what the rest of this guide is for: ask the finder in plain language, walk the rescue triage, or paste the exact error. Nothing you can do as a beginner is unrecoverable if you stop and look before typing a command marked destructive.
